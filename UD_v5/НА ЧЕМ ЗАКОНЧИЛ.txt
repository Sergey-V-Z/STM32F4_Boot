6.2 OTA — найденные баги (после полного прочтения кода):

  БАГ 1 — CRC блока проверяется сам с собой (tcp_server.cpp, CMD_FIRMWARE_DATA):
    crc = crc32_calculate(data_ptr, data_size, 0);   // вычислено на сервере
    FirmwareUpdate_ProcessDataBlock(..., crc);        // и оно же передаётся как "ожидаемое"
    → FirmwareUpdate_ProcessDataBlock сравнивает crc с crc32_calculate(...) — всегда совпадёт
    ИСПРАВЛЕНИЕ: убрать вычисление crc в tcp_server.cpp, брать CRC из заголовка пакета
    (клиент должен отправлять CRC блока в заголовке, например в поле block_number или отдельном поле)

  БАГ 2 — FirmwareUpdate_EndUpdate() после успеха запускает код сброса вместо OK:
    После успешной проверки CRC прошивки функция выполняет блок
    идентичный FirmwareUpdate_AbortUpdate() — сбрасывает контекст с error=UPDATE_ERROR_ABORT
    ИСПРАВЛЕНИЕ: после записи boot_data во внутреннюю flash установить
    g_updateContext.status = UPDATE_STATUS_COMPLETE (не IDLE!) и вернуть UPDATE_ERROR_NONE

  БАГ 3 — Вычисление номера сектора для стирания BOOT_DATA некорректно:
    eraseInit.Sector = (BOOT_DATA_ADDRESS - FLASH_BASE) / FLASH_SECTOR_SIZE;
    У STM32F407 размеры секторов НЕ одинаковые (16KB×4, 64KB×1, 128KB×7)
    деление на FLASH_SECTOR_SIZE (128KB) даёт неверный номер для первых секторов
    ИСПРАВЛЕНИЕ: вычислять номер сектора через таблицу адресов секторов STM32F407

  ЗАМЕЧАНИЕ — FirmwareUpdateTask пустая (firmware_update.cpp):
    Задача создаётся через FirmwareUpdate_StartTask() но тело цикла пустое —
    статус UPDATE_STATUS_READY_REBOOT не обрабатывается
    Сейчас перезагрузка идёт через CMD_REBOOT напрямую в tcp_server.cpp — это работает
    Задачу можно не запускать (она закомментирована в freertos.cpp — правильно)
